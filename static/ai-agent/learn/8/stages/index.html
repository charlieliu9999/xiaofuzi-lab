第 8 章 · 模型后训练
约 13 分钟对照原书：从预训练到 RL；何时选择 Mid-training、SFT 与 RL

先看失败的类型，再选训练阶段

Mid-training 补底座，SFT 稳定协议，RL 在已经能做出有差异的轨迹之后调整策略。

小结把这三件事分开：Mid-training 继续在目标分布上补知识和能力；SFT 仍是预测下一个词，但数据换成示范，用来稳住格式和协议；RL 要求当前策略已经能产生可评分、而且奖励不全一样的轨迹，才能把概率重新分配。

合理采样后 pass@k 仍接近零，说明连偶尔做对都没有，应先补底座。模型偶尔能做对，但输出无法解析，先用 SFT 把格式稳住。只有存在可比较的奖励差异，RL 才高效。

“SFT 记忆、RL 泛化”是书中受控实验里的倾向，不是一条不受数据、模型和奖励影响的定律。很多场景底座和示范够了，甚至不必做 RL。

关键词

Mid-training
在目标分布上继续学习，把标称上下文变成可用能力。
SFT
用示范把协议和格式稳住。
RL
用奖励差异强化某些轨迹、压低另一些轨迹。

三种失败不要用同一种药

模型从未写对过你们的内部 API，先补材料和能力。它会写但 JSON 经常缺字段，先给示范。它有时走通、有时违反一条可自动判断的规则，才考虑用奖励把好的轨迹变多。

给一个真实失败选阶段

请在 Cursor、Codex 或 Trae 里自己做。本页只保存笔记，不运行代码，也不调用模型。

  1. 从 Cursor、Codex 或 Trae 的使用里选一个反复出现的失败。
  2. 判断合理多试几次后，有没有至少一次做对。
  3. 若做对过，失败是格式问题还是策略问题。
  4. 只选择 Mid-training、SFT、RL 或不训练、改 Harness 四者之一，并写理由。

完成标准：理由对应失败类型，而不是“训练一下总会更好”。
