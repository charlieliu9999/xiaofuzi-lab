第 5 章 · Coding Agent 与通用 Agent
约 13 分钟对照原书：Coding Agent；项目文档化

七个工具，加一份写给 Agent 的项目说明

读、写、改、搜、跑，构成 Coding Agent 的最小工具箱。项目约定要放在仓库里，而不是只存在聊天里。

整理待办、改函数、跑测试，大体离不开读文件、写文件、局部编辑、按名搜索、按内容搜索、命令行和隔离的代码执行。这七个工具覆盖感知和执行。协作、事件和用户沟通仍然要别的工具，但它们不是写代码的最小集。

通用产品把调研、操作界面和写代码放在一起，但高效生成最后常常落到代码：文档、图表和可重复的浏览器步骤都可以固化成脚本。文件系统则存放代码、记忆和中间产物。

CLAUDE.md、AGENTS.md、.cursorrules 这一类文件在会话开始时进入上下文，写的是构建命令、风格和禁区。书中把它们和“对远程协作友好的仓库也对 Agent 友好”放在一起。Cursor 和 Codex 能利用这类约定；Trae 是否读取某一个固定文件名，要以它自己的文档为准。本课只要求约定本身写得可检查。

关键词

七个核心工具
代码执行、命令行、读、写、编辑、按文件名搜索、按内容搜索。
项目指令文件
放在仓库里、面向 Agent 的稳定行为约定。
元能力
能在运行时写出新工具、新约束或新表达，而不是预先把所有能力做死。

一份可以放进仓库的短约定

用 pnpm test 而不是 npm test。不要修改 migrations。编辑失败时先重读那一段，不要整文件覆盖。这些句子稳定、可审查，也适合作为缓存友好的前缀。

测试：pnpm test
禁区：migrations/
编辑：先读再改，保持 diff 最小

示意文本，不是原书代码。本站不会执行它。

在你的仓库里写三条约定

请在 Cursor、Codex 或 Trae 里自己做。本页只保存笔记，不运行代码，也不调用模型。

  1. 选一个你有权修改的练习仓库，不要选无关的生产库。
  2. 写下测试命令、一个禁止修改的路径、一种编辑失败后的动作。
  3. 把这三句存进该工具支持的项目规则，或先写在本课笔记里。
  4. 不要在本网站粘贴密钥或让本网站执行命令。

完成标准：三条约定不依赖某一次聊天的口头上下文。
