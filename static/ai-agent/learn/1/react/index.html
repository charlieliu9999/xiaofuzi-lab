ReAct 循环和 Harness

模型只决定下一步。组装上下文、执行工具、检查和补救，是 Harness 的工作。

ReAct 的名字只写了思考和行动，运行起来是三拍：想，做，看。模型根据当前上下文决定要不要调用工具；框架真正执行工具；结果写回轨迹，再进入下一轮，直到任务结束或被停下。

一次请求里的上下文可以分成静态前缀和轨迹。前缀通常是系统提示词加工具定义；轨迹是用户消息、模型回复和工具结果。Agent 的上下文 = 静态前缀 + 轨迹。

能跑的演示和生产系统差在 Harness。书中的生产展开是 Agent = Model + Harness，而 Harness = 上下文管理 + 工具接口 + 约束 + 验证 + 纠正。它不是另一套公式，而是把“上下文”和“工具”在生产里要承担的职责写开。

关键词

轨迹
一次任务里不断追加的消息历史。
静态前缀
对话过程中尽量保持不变的系统提示词和工具定义。
Harness
模型之外、Agent 边界之内的运行与治理代码。

退款助手的三层保障

政策放进上下文，金额和权限是约束，数据库状态用来验证，超时则重试或交人。模型仍然只负责下一步判断。

约束：单笔退款不得超过订单实付
验证：退款记录与支付单号一致
纠正：超时重试一次，仍失败就移交人工

把一次工具调用写成四行

请在 Cursor、Codex 或 Trae 里自己做。本页只保存笔记，不运行代码，也不调用模型。

  1. 设想任务是“查今天的会议并写成三条纪要”。
  2. 写出模型可能发出的工具请求，而不是最终答案。
  3. 写出框架执行后应追加的观察。
  4. 补一条约束、一条验证、一条失败后的纠正。

完成标准：你能指出哪一行是模型写的，哪一行必须由框架执行。
